# 서버 구성

냉고는 서버를 둘로 나눈다. 웹이 부르는 API는 모두 Spring 본 서버(`backend/`)가 맡고, AI 기능(채팅 답변, 레시피 검색 색인, 레시피 수집, 재료 인식)은 Python AI 서버(`ai/`)가 맡는다.

```
웹 ──HTTP·SSE──▶ Spring (MySQL) ──내부 HTTP──▶ Python (Postgres + pgvector) ──▶ Gemini API
```

## 왜 나눴나

AI 채팅은 로그인·목록 같은 기능과 성질이 다르다.

| 구분 | 로그인·목록·좋아요 | AI 채팅 |
| --- | --- | --- |
| 응답 | 짧음 | 수 초 이상, 스트리밍 |
| 비용 | 거의 없음 | 요청마다 LLM 여러 번 |
| 실패 | 드묾 | 외부 LLM 지연과 장애 |
| 바뀌는 빈도 | 드묾 | 프롬프트와 모델을 자주 실험 |

- **장애 격리:** LLM이 느려지거나 죽어도 로그인과 목록은 멀쩡해야 한다. Spring이 AI 서버 호출에 제한 시간과 동시 처리 수 제한을 건다.
- **비용과 남용 통제:** 인증, 호출 제한, 사용량 한도를 입구(Spring) 한곳에 모은다.
- **배포 분리:** 프롬프트나 모델을 바꿀 땐 AI 서버만 배포한다.
- **대가:** 서버 사이 API 계약, 부분 실패 처리(AI 서버는 답했는데 Spring 저장이 실패하는 경우), 검색 색인 동기화, 배포와 모니터링 두 벌.

이 이득은 서버를 나눈 데서 나오고 언어와는 상관없다. 본 서버를 Spring으로 고른 건 인증·트랜잭션 쪽 강점과 백엔드 취업 준비 때문이고, AI 서버를 Python으로 고른 건 LangGraph와 평가 도구가 Python 쪽에 있어서다.

## DB 테이블 주인

DB 테이블마다 그 테이블을 읽고 쓰는 주인 서버는 하나다. 남의 테이블은 직접 읽거나 쓰지 않고 주인 서버의 API를 부른다.

| 주인 | 테이블 |
| --- | --- |
| Spring (MySQL) | 사용자, 프로필, 냉장고 재고, 재료 인식 작업 상태, 채팅방과 메시지(대화 기록의 정본), 좋아요, 스크랩, 레시피 원본, 재료 표준 사전(알레르기 코드, 기본 보관 기간) |
| Python (Postgres) | 검색 색인(레시피 임베딩과 필터용 사본, 재료 표준 사전 사본), 수집 작업 테이블(긁어 온 원본과 검수 상태) |

- 레시피나 재료 표준 사전이 생기거나 바뀌면 Spring이 Python의 색인 API를 부른다. 이 호출이 실패할 때를 대비해 전체 재색인 명령도 둔다.
- 수집은 Python이 긁고 정리한 뒤, 완성된 레시피를 Spring 내부 API로 넣는다.
- Python이 검색하다가 Spring을 되부르지 않는다(순환 호출). 검색 색인은 검색하는 쪽이 갖는다.
- AI 서버는 대화 기록을 따로 갖지 않는다. Spring이 요청마다 최근 대화를 실어 보낸다.

## 채팅 한 번이 오가는 흐름

1. 웹이 Spring에 메시지를 보낸다(SSE 연결).
2. Spring이 사용자 메시지를 먼저 저장하고 AI 메시지를 생성 중 상태로 만든 뒤, 프로필(알레르기 등)과 최근 대화를 읽는다. 같은 방이 이미 답변 중이면 409로 막는다.
3. Spring이 Python에 내부 HTTP로 메시지, 최근 대화, 프로필, 사용자 id를 보낸다.
4. Python이 답변을 SSE로 흘려보내고, 마지막에 추천 레시피 id를 붙인다.
5. Spring은 받은 글자를 그대로 웹에 중계하고, 끝나면 AI 메시지를 완료 상태로 저장하고 레시피 카드 내용을 MySQL 원본에서 채운다. 중간에 실패하면 실패 상태로 남긴다.

## 재료 인식 (뒤로 미룸)

사진·영상으로 재료를 인식하는 기능은 채팅(RAG)을 먼저 다듬은 뒤에 만든다. 그때까지 재고는 글로 입력한다. 정해 둔 흐름은 이렇다.

1. 웹이 사진이나 영상을 미리 서명된 주소(presigned URL)로 S3에 올리고, 파일 키를 Spring에 보낸다.
2. Spring이 인식 작업을 대기 상태로 만들고 Python에 파일 키를 넘긴다.
3. Python이 Gemini로 재료·양·산 날 후보를 뽑고, 재료 표준 사전 사본에 맞춰 재료 id를 붙여 돌려준다.
4. 사용자가 확인하거나 고친 것만 재고에 들어간다.
